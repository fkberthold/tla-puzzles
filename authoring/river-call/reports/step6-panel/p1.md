# RiverCall, seat p1

## 1. Spec and cfg, verbatim
RiverCall.tla:
```
---- MODULE RiverCall ----
EXTENDS Naturals
CONSTANTS Owners, Decree, Flow
ASSUME Owners \subseteq Nat /\ Flow \in Nat
Decrees == [o \in Owners |-> 2]
Senior(a, b) == a < b   \* the name is the date; the smaller number is the older right
VARIABLES gate, call
vars == <<gate, call>>
RECURSIVE SumOver(_, _)
SumOver(f, S) == IF S = {} THEN 0
                 ELSE LET x == CHOOSE y \in S : TRUE IN f[x] + SumOver(f, S \ {x})
Total(g) == SumOver(g, Owners)
Free(g) == Flow - Total(g)
Short(g, o) == g[o] + Free(g) < Decree[o]                       \* rule 5
Init == gate = [o \in Owners |-> 0] /\ call = [o \in Owners |-> FALSE]   \* rule 10
Set(o, n) ==                                                    \* rule 3
  /\ n /= gate[o]
  /\ n - gate[o] <= Free(gate)                                  \* rule 4
  /\ n > gate[o] => \A s \in Owners : Senior(s, o) => ~call[s]  \* rule 7
  /\ gate' = [gate EXCEPT ![o] = n] /\ UNCHANGED call
PutCall(o) == ~call[o] /\ Short(gate, o)                        \* rule 6
              /\ call' = [call EXCEPT ![o] = TRUE] /\ UNCHANGED gate
Withdraw(o) == call[o] /\ call' = [call EXCEPT ![o] = FALSE] /\ UNCHANGED gate
Next == \E o \in Owners : PutCall(o) \/ Withdraw(o) \/ \E n \in 0..Decree[o] : Set(o, n)
Spec == Init /\ [][Next]_vars
Observe == [diverted |-> gate, calling |-> call]
GatesWellFormed ==
  /\ DOMAIN Observe.diverted = Owners /\ DOMAIN Observe.calling = Owners
  /\ \A o \in Owners : Observe.diverted[o] \in 0..Decree[o] /\ Observe.calling[o] \in BOOLEAN
TheFlowHolds == Total(Observe.diverted) <= Flow
NobodyOpensAgainstACall ==
  [][\A o \in Owners : Observe'.diverted[o] > Observe.diverted[o]
       => \A s \in Owners : Senior(s, o) => ~Observe.calling[s]]_Observe
ACallIsHonest ==
  [][\A o \in Owners : (~Observe.calling[o] /\ Observe'.calling[o])
       => Short(Observe.diverted, o)]_Observe
====
```
Check.cfg (shipped RiverCall.cfg is this with `Flow = 6`; names matched, no edit; both fences drop blank lines only):
```
SPECIFICATION Spec
CONSTANTS
    Owners = {1, 2, 3}
    Decree <- Decrees
    Flow = 3
INVARIANTS
    GatesWellFormed
    TheFlowHolds
PROPERTIES
    NobodyOpensAgainstACall
    ACallIsHonest
```

## 2. TLC result
`tlc -workers 1 -config Check.cfg RiverCall.tla`: rc 0, 757 generated, **136 distinct**, depth 8, deadlock checking on.
`tlc -workers 1 -config RiverCall.cfg RiverCall.tla` (flow 6): rc 0, 163 generated, 27 distinct, depth 4: the shipped run, number for number.
136 = 17 gate vectors with total <= 3 times 8 call vectors, so the model carries the two facts and nothing else.

## 3. Traces

run as written and checks the four formulas over it (`-deadlock`, a finite run ends). `ModelSpec` walks it only along
steps `RC!Next` allows and checks `i < Len(Trace)`: a violation means the model walked it all, rc 0 means it stuck.
| pair | forbidden run: rejected by                                                     | model walks it?      | allowed run: four checks | model walks it? |

| 1    | TheFlowHolds, rc 12, state 2: 2+2 > 3                                          | no, stuck at state 1 | rc 0, all pass           | yes, i = 3      |
| 2    | NobodyOpensAgainstACall, rc 13, step 3->4: owner 3 rises 0->1 under 2's call   | no, stuck at state 3 | rc 0, all pass           | yes, i = 4      |

## 4. Attempts
One. The first draft was clean on both instances; nothing revised, TLC caught no bug. The one choice made before
running: `Set` requires `n /= gate[o]`, because 163 generated over 27 states is 27*6+1, which says the reference
excludes a same-setting step (allowing it would read 27*9+1 = 244). The mutants in 7 are what shows the checks bite.

## 5. Not carried over the interface
Rule 3's "only their own gate" and rule 8, as the statement says: Observe has no actor field. Rule 9 is the absence
of fairness in `Spec`. Rule 7's "whatever happens to the call in the same act" is carried by construction, not by a
check: each action moves one field of one owner, so a rise and a withdrawal are never one step. All else is checked.

## 6. Unclear or wrong
- "Any owner set", but only the checking section orders seniority (name = date). I took `<` on Owners: an unstated `Owners \subseteq Nat`.
- Rule 7's "whatever happens to the call in the same act" suggests an act can withdraw a call and open a gate at
  once; rules 3 and 6 make those two separate acts. No trace needs a combined act and I modelled none.
- The statement calls the flow-6 model "correct" as a fact; it is the claim under test (section 7).

## 7. The green run
**Q1, what it establishes.** On flow 6 the model starts shut, every gate stays in 0..2, no total passes 6, and
every rise and every call TLC saw was lawful. 27 = 3^3 distinct states says the reachable graph is the gate vectors
alone with no call ever standing; depth 4 is three rises from shut. So: well typed, and nobody ever calls there.
**Q2, what it fails to establish:** that rules 4, 5, 6 and 7 are in the model at all. Flow 6 equals the sum of the
decrees, so `gate[o] + Free = 6 - others >= 6 - 4 = 2 = Decree[o]`: nobody is ever short. `Probe.tla` checks
`NoOneShort` and `NoCallStands` as invariants: flow 6 rc 0 over all 27 states; flow 3 violates NoOneShort at state 3.
So ACallIsHonest judges zero call steps, NobodyOpensAgainstACall's antecedent (a senior calling) is never true, and
the flow cap never binds since no in-range vector totals more than 6: TheFlowHolds is implied by GatesWellFormed.
Evidence: five mutants, each one sed edit of RiverCall.tla (`mutants/`, diffs checked), run on both cfgs:
| mutant                                          | flow 6, shipped cfg              | flow 3, checking cfg                          |
|-------------------------------------------------|----------------------------------|-----------------------------------------------|
| MutNo7: rule 7 guard deleted                    | rc 0, 163/27/depth 4, identical  | rc 13, NobodyOpensAgainstACall                |
| MutRev7: seniority backwards in rule 7          | identical green                  | rc 13, NobodyOpensAgainstACall                |
| MutNo4: rule 4 guard deleted                    | identical green                  | rc 12, TheFlowHolds                           |
| MutNoCall: PutCall and Withdraw out of Next     | identical green                  | rc 0, all four pass, 17 states                |
| MutFreeCall: Short guard off PutCall            | rc 13, ACallIsHonest             | rc 13, ACallIsHonest                          |
Four wrong models reproduce the shipped output byte for byte; the run catches only a call with no guard at all.
MutNoCall passes all four checks on every instance; only the state count (17, not 136) and the allowed runs expose
it (`TracesNoCall.tla`, Traces over MutNoCall: stuck on pair 2's and pair 3's allowed runs, rc 0; walks pair 1's).
The behavior the rules allow and flow 6 cannot show, from TLC's MutNo7 counterexample on flow 3: (0,0,0) no calls;
owner 1 sets 2; owner 2 is short (0 + 1 free < 2) and calls; owner 3 rises 0->1 against the call. At flow 6 owner 2
is never short, the call never goes out, the rise is lawful, and a model with rule 7 missing is green.
Answer: green means the formulas hold where no rule can bind, not that the model is right; they bite only at
Flow < sum of decrees, which is why 3 is the checking instance.

## 8. Mechanism family
Yes, on the first read: "first in time, first in right" plus a call that freezes juniors' new takes is a priority
register with a hold flag, a no-preemption priority lock. Not a published TLA+ problem I know. It did not change the model.
