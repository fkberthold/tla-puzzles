# RiverCall — panel seat p2
## 1. Spec and cfg, verbatim — `RiverCall.tla`, blank lines stripped for the line budget
```tla
---------------------------- MODULE RiverCall ----------------------------
\* A stretch of stream under prior appropriation.
EXTENDS Integers
CONSTANTS Owners,  \* the ditch owners. The name IS the priority date.
          Decree,  \* Owners -> Nat, the decreed amount
          Flow     \* whole units the stream carries past the stretch
VARIABLES gate,    \* Owners -> Nat, the setting on each headgate
          call     \* Owners -> BOOLEAN, whose call stands on the river
vars == << gate, call >>
Decrees == [o \in Owners |-> 2]
RECURSIVE SumOf(_, _)
SumOf(f, S) == IF S = {} THEN 0
               ELSE LET x == CHOOSE y \in S : TRUE
                    IN  f[x] + SumOf(f, S \ {x})
Taken(d)     == SumOf(d, Owners)      \* water going down ditches
Free(d)      == Flow - Taken(d)       \* water nobody is taking
Short(d, o)  == d[o] + Free(d) < Decree[o]      \* rule 5
Senior(a, b) == a < b                 \* an older date is a smaller name
Init == gate = [o \in Owners |-> 0] /\ call = [o \in Owners |-> FALSE]
\* Rules 3, 4, 7. One owner, one gate, one act: inside the owner's own decree,
\* never past the flow, never UP while an owner senior to them is calling.
MoveGate(o, v) ==
  /\ v # gate[o]
  /\ Taken([gate EXCEPT ![o] = v]) <= Flow
  /\ (v > gate[o]) => (\A s \in Owners : Senior(s, o) => ~call[s])
  /\ gate' = [gate EXCEPT ![o] = v] /\ UNCHANGED call
\* Rule 6. Only a short owner calls; anyone takes their own back, any time.
PutCall(o)  == /\ ~call[o] /\ Short(gate, o)
               /\ call' = [call EXCEPT ![o] = TRUE]  /\ UNCHANGED gate
DropCall(o) == /\ call[o]
               /\ call' = [call EXCEPT ![o] = FALSE] /\ UNCHANGED gate
Next == \E o \in Owners : \/ \E v \in 0..Decree[o] : MoveGate(o, v)
                          \/ PutCall(o) \/ DropCall(o)   \* rules 1, 8, 9
Spec == Init /\ [][Next]_vars
Observe == [diverted |-> gate, calling |-> call]   \* the interface
\* The four requirements, over Observe and the constants only.
GatesWellFormed ==
  /\ DOMAIN Observe.diverted = Owners /\ DOMAIN Observe.calling = Owners
  /\ \A o \in Owners : Observe.diverted[o] \in 0..Decree[o]
  /\ \A o \in Owners : Observe.calling[o]  \in BOOLEAN
TheFlowHolds == Taken(Observe.diverted) <= Flow
NobodyOpensAgainstACall ==
  [][ \A o \in Owners : (Observe'.diverted[o] > Observe.diverted[o])
        => (\A s \in Owners : Senior(s, o) => ~Observe.calling[s]) ]_Observe
ACallIsHonest ==
  [][ \A o \in Owners : (Observe'.calling[o] /\ ~Observe.calling[o])
        => Short(Observe.diverted, o) ]_Observe
=============================================================================
```

## 3. The traces
Checked by machine. `Traces.tla` replays a run row by row into `gate`/`call`. `TSpec` replays it alone, so the four
requirements grade the run itself; `MSpec` conjoins each step with `RiverCall!Next`, so reaching the last row — a
violation of `NotFinished == idx < Len(Trace)` — proves my model produces it. Both `-deadlock`.
- **pair 1** allowed: accepted, all 3 rows. Forbidden: **TheFlowHolds** at row 2 (1 and 2 take 4 on a flow of 3); stalls at row 1.
- **pair 2** allowed: accepted, all 4 rows. Forbidden: **NobodyOpensAgainstACall** at row 4; stalls at row 3.
- **pair 3** allowed: accepted, all 3 rows. Forbidden: **ACallIsHonest** at row 2 (nobody short); stalls at row 1.
My set rejects **no** allowed run; one pair per requirement, as promised. Two hand-built runs test rule 7's last
clause both ways: `T7`, a junior rising in the same act the caller drops the call, is rejected by requirement 3;
`T8`, the call going out in the same act as the rise, is accepted. A property reading `Observe'.calling` would
get `T8` wrong, so this pins the pre-state reading instead of asserting it. Each requirement also kills a mutant
of my own spec at flow 3: drop the rule-7 guard → `NobodyOpensAgainstACall` (rc 13); drop `Short(gate, o)` →
`ACallIsHonest` (rc 13); drop the flow guard → `TheFlowHolds` (rc 12); widen the range to `Decree+1` →
`GatesWellFormed` (rc 12). None of the four is inert.
## 4. Attempts
One. The first draft ran clean at 136 and TLC caught no bug in it. Two design points were settled before that run
by arithmetic rather than by TLC, the weaker evidence: `v # gate[o]` and one-owner-per-step are both forced by
163 = 27×6 + 1 on the shipped instance. Later edits were cosmetic, every run repeated after.
## 5. What I could not carry over the interface
Nothing past the two the statement names. Rule 3's "each owner sets only their own" and rule 8 are not properties
of `Observe`: whose hand moved a gate is not in the record, and `MoveGate` enforces it in Next where no property
can see it. Rule 9 is uncheckable for the opposite reason — it says nothing must happen, which a safety-only spec
with no fairness already asserts.
## 6. Unclear or wrong in PROBLEM.md
Nothing wrong. One real ambiguity: rule 7's "whatever happens to the call in the same act" describes a step my model
cannot produce, gate moves and call moves being separate acts. I read it as fixing where the property *reads* the
call — the pre-state — not as licensing combined acts; `T7`/`T8` are that reading made executable.
## The two questions on the green run
**Establishes.** On that instance and only there, exhaustively: the interface is well typed, the flow bound holds,
the graph is deadlock-free, and no call is ever put out. 27 distinct = 27 gate vectors (all fit a flow of 6) × 1.
**Fails to establish, and why.** Three decrees of 2 against a flow of 6 exhaust the stream exactly, so
`gate[o] + Free = 6 − (what the others take) ≥ 6 − 4 = 2 = Decree[o]`: **nobody can ever be short**, so nobody
can lawfully call, so the call machinery is unreachable and requirements 3 and 4 grade an empty set of steps.
Requirement 2 is idle for a second reason — three decrees of 2 cannot overdraw a flow of 6 at all. `Probe.tla` holds
over the complete flow-6 graph, rc 0 (`NobodyIsEverShort`, `NoCallEverStands`, `NoJuniorIsEverPinned`); at flow 3 it
fails at depth 3.
That this is fatal and not merely narrow: I deleted the rule-7 guard from my own spec, so a junior may open straight
into a senior's standing call, and ran it against the shipped `RiverCall.cfg`. **rc 0, no error, 163 states
generated, 27 distinct, depth 4** — the correct model's numbers, digit for digit. Deleting the flow guard gives the
same. Both die at flow 3. The green run cannot tell my model from two broken ones, so the claim does not follow.
Against my own case: requirement 4 is *not* fully vacuous there. Deleting the honesty guard does fail on the shipped
cfg (rc 13), because with nobody ever short "a call goes out honestly" collapses into "no call ever goes out". So
the run establishes that this model emits no call there — nothing about which are honest, that set being empty.
The allowed behavior no check on that instance can see, TLC's own counterexample from the rule-7 mutant at flow 3,
which is the pair-2 forbidden run rediscovered: (0,0,0)/no calls → owner 1 opens to 2 → owner 2 is short (0 + free
1 < 2) and calls → owner 3, junior to the caller, opens to 1 against it. At flow 6 that third state cannot exist.
## 7. Recognition
No. I recognized the mechanism family on the first read of rules 6 and 7 — a priority-ordered advisory lock with no
lock manager, where a holder blocks acquisitions below it and never revokes what is already held. That shaped the
state, nothing else. Not recognized as a published problem at any point, and I did not go looking.
