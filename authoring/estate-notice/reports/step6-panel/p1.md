# The executor's notice, seat p1

## 1. Spec and cfg, verbatim (the text every run below used)
```tla
---- MODULE EstateNotice ----
\* The executor's notice. State is exactly the three facts Observe reports.
CONSTANT Creditors
VARIABLES standing, notice, distributed
vars == <<standing, notice, distributed>>
Standings == {"none", "lodged", "admitted", "paid", "rejected", "outOfTime"}
Unsettled == {"lodged", "admitted"}  \* lodged with her and not yet settled (Rule 7)
TypeOK == standing \in [Creditors -> Standings] /\ notice \in {"open", "closed"} /\ distributed \in BOOLEAN
Init == standing = [c \in Creditors |-> "none"] /\ notice = "open" /\ distributed = FALSE
Move(c, s) == standing' = [standing EXCEPT ![c] = s] /\ UNCHANGED <<notice, distributed>>
\* Creditor steps (Rules 3, 4). No fairness on these.
Lodge(c)           == notice = "open"   /\ standing[c] = "none" /\ Move(c, "lodged")
ComeForwardLate(c) == notice = "closed" /\ standing[c] = "none" /\ Move(c, "outOfTime")
\* Executor steps (Rules 2, 5, 6, 7). Weak fairness on each.
Close      == notice = "open" /\ notice' = "closed" /\ UNCHANGED <<standing, distributed>>
Admit(c)   == standing[c] = "lodged"   /\ Move(c, "admitted")
Reject(c)  == standing[c] = "lodged"   /\ Move(c, "rejected")
Decide(c)  == Admit(c) \/ Reject(c)  \* Rule 9 obliges a decision, not a particular one
Pay(c)     == standing[c] = "admitted" /\ Move(c, "paid")
Distribute == /\ notice = "closed" /\ ~distributed
              /\ \A c \in Creditors : standing[c] \notin Unsettled
              /\ distributed' = TRUE /\ UNCHANGED <<standing, notice>>
Next == \/ \E c \in Creditors : Lodge(c) \/ ComeForwardLate(c) \/ Decide(c) \/ Pay(c)
        \/ Close
        \/ Distribute
\* Rule 9: she owes the winding up; the creditors owe nothing. Each of her steps,
\* once enabled, stays enabled until she takes it, so weak fairness is enough.
Fairness == /\ WF_vars(Close) /\ WF_vars(Distribute)
            /\ \A c \in Creditors : WF_vars(Decide(c)) /\ WF_vars(Pay(c))
Spec == Init /\ [][Next]_vars /\ Fairness
Observe == [standing |-> standing, notice |-> notice, distributed |-> distributed]
\* The eight requirements over Observe. Each step rule's subscript is the one
\* field whose change can make it fail; a step that leaves that field alone
\* cannot fire the rule's antecedent, so skipping it loses nothing.
Clear == Observe.distributed =>  \* 1
  Observe.notice = "closed" /\ \A c \in Creditors : Observe.standing[c] \notin Unsettled
ClaimStartsInWindow == [][\A c \in Creditors :  \* 2
    Observe.standing[c] = "none" /\ Observe'.standing[c] # "none" =>
      \/ (Observe.notice = "open"   /\ Observe'.standing[c] = "lodged")
      \/ (Observe.notice = "closed" /\ Observe'.standing[c] = "outOfTime")
  ]_(Observe.standing)
LodgedEndsInDecision == [][\A c \in Creditors :  \* 3
    Observe.standing[c] = "lodged" /\ Observe'.standing[c] # "lodged" =>
      Observe'.standing[c] \in {"admitted", "rejected"}]_(Observe.standing)
DecisionStands == [][\A c \in Creditors :  \* 4
    /\ Observe.standing[c] = "admitted" => Observe'.standing[c] \in {"admitted", "paid"}
    /\ Observe.standing[c] \in {"rejected", "paid", "outOfTime"} =>
         Observe'.standing[c] = Observe.standing[c]
  ]_(Observe.standing)
NoticeNeverReopens == [][Observe.notice = "closed" => Observe'.notice = "closed"]_(Observe.notice)  \* 5
DistributionStays == [][Observe.distributed => Observe'.distributed]_(Observe.distributed)  \* 6
EventuallyDistributed == <>Observe.distributed  \* 7
OneAtATime == [][\A c, d \in Creditors :  \* 8
    c # d /\ Observe.standing[c] # Observe'.standing[c] =>
      Observe'.standing[d] = Observe.standing[d]]_(Observe.standing)
====
```
```
SPECIFICATION Spec
CONSTANT Creditors = {c1, c2}
INVARIANT TypeOK
INVARIANT Clear
PROPERTY ClaimStartsInWindow
PROPERTY LodgedEndsInDecision
PROPERTY DecisionStands
PROPERTY NoticeNeverReopens
PROPERTY DistributionStays
PROPERTY EventuallyDistributed
PROPERTY OneAtATime
```

## 2. TLC on the model
`tlc -workers 1 -deadlock EstateNotice.tla`: rc=0, 138 states generated, 77 distinct, depth 9, all eight hold (main-run.log). TypeOK is my own sanity invariant.

## 3. Traces (gen-traces.py transcribes traces/ into TraceEstate.tla; check/run-matrix.sh runs it; check/matrix.txt)
Produce: Init and Next are forced to follow the run's rows; TLC finds Len(run) distinct states iff the model can make every step. Replay: the rows are followed verbatim, whatever Next says, then stutter forever; each property is held against that on its own, so the rejecting property is named by TLC and not by me.
Allowed: all eight reproduced (distinct = length: 5,4,3,4,3,4,6,5), and the seven safety properties hold on every allowed replay.
Forbidden, rejecting property (replay rc) and where the model blocks the run (Produce distinct / length):
- P1 Clear (rc 12), 3/4. P2 ClaimStartsInWindow (13), 2/3. P3 LodgedEndsInDecision (13), 2/3. P4 DecisionStands (13), 3/4.
- P5 NoticeNeverReopens (13), 2/3. P6 DistributionStays (13), 3/4. P8 OneAtATime (13), 3/4.
- P7 EventuallyDistributed (13) and nothing else. Produce reproduces all 6 rows: every step is legal and the fault is the stall. The model rules it out by WF_vars(Close), not by Next (mutant `noclose` below reproduces this exact shape).
EventuallyDistributed also rejects every other forbidden replay and every allowed replay: a replay stutters at its last row and none reaches distributed. That is the replay having no fairness, not my set rejecting an allowed run. Each allowed run is a produced prefix of Spec, and Spec satisfies <>distributed (section 2), so each extends to a run that distributes.

## 4. Attempts
One draft of the model; TLC was clean on the first run at 77 states and caught nothing in it. The trace harness took two fixes before it ran (missing EXTENDS Naturals; then the mutant generator put actions after Next, which TLA+ forbids, and its marker split had a doubled backslash). Revised once mid-way: reformatted the module from 133 lines to 56 to fit this report, then re-ran the main check, the matrix and the mutants against the new text; every number here is from those re-runs.
Mutants (mutants/make-mutants.py builds them from EstateNotice.tla; mutants/results.txt):
- reopen: adds a Reopen step. NoticeNeverReopens is VIOLATED (rc 13, 14 states). The same formula under _(Observe.standing) holds over 88 states: the step changes no standing, so the narrow subscript never looks at it.
- latelodge: adds lodging after close. ClaimStartsInWindow VIOLATED (rc 13). Under _(Observe.notice) it holds over 77 states, for the same reason.
- fairness, holding <>distributed against five Specs over the same Next: no fairness FAILS (she stalls after c2 comes forward late); no WF(Close) FAILS with both claims rejected and the notice open forever, the pair-7 shape; no WF(Distribute) FAILS; WF on the creditors' steps only FAILS; WF_vars(Next) HOLDS, as the statement warns. So the fairness is on her steps and on no fewer of them.

## 5. Not carried over the interface
None. Rule 8 needs no formula: after Distribute no executor step is enabled (Close needs open; Decide and Pay need lodged or admitted, which Rule 7 clears first). Rule 1's one-claim-only and no-withdrawal follow from 2, 3 and 4 together: nothing returns to none. Rule 6's "never in the same motion" is 3 and 4: lodged cannot reach paid in one step.

## 6. Unclear or wrong in PROBLEM.md
- No requirement forbids a single step that changes two Observe fields, say close-and-lodge or admit-and-distribute. Requirement 8 watches creditors, none watches fields. My model never does it, and nothing in the traces can show it.
- Rule 7 "every claim lodged with her": I read none and outOfTime as no claim lodged, so Distribute ignores them; pair 6 allowed (c1 comes forward after distribution) is consistent. If none were meant to block, the state count would not be 77.
- The 77 held for me, and the arithmetic behind it (25 open + 36 closed + 16 distributed) is worth stating in the text; a learner whose count is off has nothing to compare against.
- On blanket fairness: the statement's reason is right. Every state short of the end has some step enabled, so WF_vars(Next) drives every run to the end without naming whose step it was. The `blanket` mutant confirms it holds.

## 7. Mechanism
Recognized at the first paragraph as a claims window with a bar date: register while open, late arrivals redirected rather than lost. Not, to my knowledge, a published TLA+ problem; I did not look for one.
