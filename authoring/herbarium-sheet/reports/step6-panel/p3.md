## 7. Mechanism Recognition
Recognized this as a **version control / amendment history system** after modeling the consultation-filing pattern: botanists consult sheets (like opening documents), mark them doubtful (request review), and file determinations (commit name changes). The consultation stamp acts as a version counter, preventing mid-flight modifications. This pattern appears in configuration management, document versioning, and consensus protocols.

## Req5 Diagnostic Questions

**Question 1: What does the green run establish about your model?**
The green TLC run establishes that the formula DoubtClearsOnlyOnFiling holds for every behavior trace of the model. Specifically: whenever a sheet transitions from doubted=TRUE to doubted=FALSE, a new slip must appear on that sheet in the same step. This holds in all 259 distinct states and all 1289 generated state transitions.

**Question 2: What does it fail to establish, and why?**
The green run fails to establish:
- **Temporal completeness of Req5**: That doubt actually gets cleared (leads-to property). Req5 only states the implication when doubt clears; it doesn't guarantee doubt ever clears. That obligation belongs to Req6 (eventually-answered).
- **Model correctness**: Whether the model accurately captures the real herbarium rules. Req5 could be satisfied by a model that forbids doubt entirely, which vacuously satisfies the formula. Only Req1-Req4,Req7 provide positive constraints on when doubt can exist.
- **Slip authenticity**: Whether slips themselves are valid. Req5 checks the timing relationship between doubt-clearing and slip-filing, but not whether slip names/stamps are correct. Req1 and Req4 cover that.
- **Independence from initial conditions**: The check assumes the initial state is correct (no doubt, no slips). Req7 grounds this, but Req5 alone doesn't verify the opening.

The formula Req5 is a **safety property** (something bad never happens); it cannot establish liveness properties (something good eventually happens) without fairness. The model's weak fairness on File makes Req6 work, but Req5 has no fairness component and thus no guarantee of eventual clearing.
