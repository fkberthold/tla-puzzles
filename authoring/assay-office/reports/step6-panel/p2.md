# The assay office — seat p2

**1. The three properties and the cfg, verbatim.** Appended below `FairSpec`
in `AssayOffice.tla`; nothing above it was touched. Blank lines between the
four definitions are dropped here for length.

```tla
MarkAndDefaceFollowFinding ==
    \A w \in Wares :
        /\ Observe.marked[w]  => Observe.finding[w] = "atStandard"
        /\ Observe.defaced[w] => Observe.finding[w] = "substandard"
Grows(o, p) ==
    \A w \in Wares :
        /\ o.finding[w] # "none" => p.finding[w] = o.finding[w]
        /\ o.marked[w]           => p.marked[w]
        /\ o.defaced[w]          => p.defaced[w]
RecordOnlyGrows == [][ Grows(Observe, Observe') ]_Observe
SubstandardIsDischarged ==
    \A w \in Wares :
        (Observe.finding[w] = "substandard") ~> Observe.defaced[w]
```

Req 1 needs no "not both" conjunct: one finding per ware, and the two
antecedents demand different findings. `Grows` takes two records so the
formula does not turn on how `Observe'.finding[w]` parses.

```
SPECIFICATION FairSpec
CONSTANTS Wares = {w1, w2, w3}   Officers = {o1, o2}
INVARIANT MarkAndDefaceFollowFinding
PROPERTY RecordOnlyGrows   SubstandardIsDischarged
CHECK_DEADLOCK FALSE
```

**2. TLC on the shipped spec.** `tlc -workers 1 -config AssayOffice.cfg
AssayOffice.tla` → **rc=0**, "No error has been found", **601 states
generated, 125 distinct**, depth 7. The 125 matches `PROBLEM.md`, so the
system half is unchanged (`out-final.txt`).

**3. The traces, replayed mechanically.** `TraceCheck.tla` writes all twelve
runs out as sequences of `book` values and walks one per run under `WF(TNext)`,
so TLC follows the whole run and stutters only at its last state. The
properties come in through `INSTANCE AssayOffice`, so the harness cannot check
a formula other than the cfg's. `run-traces.sh` runs all 12 × 3:

```
allowed:    all six PASS all three properties; none rejected by anything
forbidden:  p1 → Req1   p2 → Req2, Req3   p3 → Req3
            p4 → Req1   p5 → Req2         p6 → Req2, Req3
```

Every forbidden run is rejected, and the primary mapping is two / three / one
as `PROBLEM.md` says. Req3's extra catches on pairs 2 and 6 are runs ending on
an undischarged substandard finding — secondary, which `PROBLEM.md` allows.
`run-mutants.sh` then cuts one guard out of the shipped text at a time, so
each property is shown to have teeth (logs `out-mut-*.txt`):

| variant | Req1 | Req2 | Req3 |
|---|---|---|---|
| `MutantStrike` — strike guard removed | **FAIL** | PASS | PASS |
| `MutantUnstrike` — a struck ware can be un-struck | PASS | **FAIL** | PASS |
| `MutantRetest` — "tested once" guard removed | FAIL | **FAIL** | FAIL |
| shipped spec under `SPECIFICATION Spec` | PASS | PASS | **FAIL** |

The first two are isolated — one property fires, so each is evidence for that
property alone. `MutantRetest` fires all three and is confounded, which is why
`MutantUnstrike` exists as the clean Req2 witness. The last row is the failure
`PROBLEM.md` predicts for dropping fairness, naming exactly
`SubstandardIsDischarged`. I ran the subscript trap too: `Req2BadSubscript` is
the same action subscripted over `Observe.finding`, and against the un-strike
mutant it returns **rc=0, no error** where `_Observe` returns rc=13.

**4. Attempts, and what got revised.** TLC was clean on the shipped spec on the
**first** attempt and never caught a bug in any of the three properties. I
revised none of them. It caught two bugs of mine elsewhere. First, my **trace
harness**: the original `TSpec` had no fairness, and three *allowed* runs came
back FAIL on Req3, the counterexample showing the replay stop at state 3 of a
four-state run and stutter there with w1 substandard and whole. Unfaired, the
harness replays every *prefix*, and a prefix can sit on an obligation the full
run discharges; `WF(TNext)` fixed it. That looked like three false rejections
by my property and was my harness misquoting the traces. Second, a claim I had
written into item 6 — recorded there.

**5. What I could not carry over the interface.** Nothing the three
requirements ask for. Three other stated rules cannot be reached through
`Observe`, and none needed to be. **Rule 1's fixed ware set and rule 6's
"nothing leaves"**: the fields are functions on the constant `Wares`, so no
ware can arrive or depart by construction, and `DOMAIN Observe.finding = Wares`
is statable but vacuous. **Officers**: `Observe` does not expose them, so their
interchangeability and non-coordination are facts about the spec's structure,
invisible to a property over it. **Rule 5, the absence of obligation**: "a ware
may lie untested forever" says something is *not* required — about what the spec
admits, not what every behavior satisfies — so no `PROPERTY` says it. Untested.

**6. `PROBLEM.md`.** Neither quantifier in the fairness conjunct is
load-bearing, and the hint implies both are. `PROBLEM.md` sends the learner to
`FairSpec` for "what the obligation is quantified over"; `Deface(o, w)` never
mentions `o`, so that quantifier states one formula twice. I then wrote here
that `w` *was* load-bearing, on the usual starvation argument, and built
`WeakFair.tla` to prove it — the shipped spec with one `WF_vars(\E w :
Deface(w))` for the per-ware family. **TLC refuted me**: rc=0, 125 distinct
states (`out-weakfair.txt`). Defacing is one-shot per ware and `Wares` finite,
so no behavior holds more than three deface steps and "infinitely often a
deface step" is unsatisfiable, forcing WF's other side; a substandard-and-whole
ware stays enabled until defaced. The per-ware split would matter if defacing
were repeatable. Here it buys nothing.

Second: Req3 is liveness and every trace is finite, so a trace pins it down
only once you know what follows the last state. `PROBLEM.md` says so for pair
3's forbidden run and nowhere else. The reading is plainly "stutter forever",
and under it every allowed run is clean — I checked that all six end with no
undischarged substandard finding. Stating that as a convention would help.

**7. The mechanism.** Recognized the family, not the problem, on first reading
`AssayOffice.tla` before writing anything: a write-once field plus two absorbing
booleans per key is a **monotone per-item record**, Req2 is the standard
stability obligation over it, and Req3 the standard "pending obligation
eventually discharged" — a leads-to made true by weak fairness. I have not seen
this dressing before, do not think it a published problem, and did not look.
