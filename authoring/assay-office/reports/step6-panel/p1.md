# The assay office, seat p1

## 1. The properties (added to AssayOffice.tla after FairSpec) and the cfg, verbatim

    FindingGoverns ==
        \A w \in Wares :
            /\ Observe.marked[w]  => Observe.finding[w] = "atStandard"
            /\ Observe.defaced[w] => Observe.finding[w] = "substandard"
            /\ ~(Observe.marked[w] /\ Observe.defaced[w])

    RecordGrows ==
        \A w \in Wares :
            /\ Observe.finding[w] /= "none" => Observe'.finding[w] = Observe.finding[w]
            /\ Observe.marked[w]  => Observe'.marked[w]
            /\ Observe.defaced[w] => Observe'.defaced[w]

    RecordOnlyGrows == [][RecordGrows]_Observe

    SubstandardDischarged ==
        \A w \in Wares : (Observe.finding[w] = "substandard") ~> Observe.defaced[w]

AssayOffice.cfg:

    SPECIFICATION FairSpec
    CONSTANTS
      Wares = {w1, w2, w3}
      Officers = {o1, o2}
    INVARIANT FindingGoverns
    PROPERTY RecordOnlyGrows
    PROPERTY SubstandardDischarged
    CHECK_DEADLOCK FALSE

The third conjunct of FindingGoverns follows from the first two, since one finding cannot be both
names. It is written out because requirement 1 states it.

## 2. TLC on the shipped spec

`tlc -workers 1 -cleanup -config AssayOffice.cfg AssayOffice.tla`, TLC2 Version 2026.07.31.184830:
rc=0, 601 states generated, 125 distinct states, "No error has been found" (run-fair.log:29,33).

Control: the same module and properties with `SPECIFICATION Spec` (AssayOffice-nofair.cfg, run in
nofair/): rc=13, "Temporal property SubstandardDischarged was violated", 125 distinct states. The
counterexample writes w1 substandard and ends "State 7: Stuttering" (run-nofair.log:28-73). That is
the failure PROBLEM.md predicts for Spec, and it shows requirement 3 is not vacuous on this model.

## 3. The traces

Method: TraceCheck.tla declares `book` and an index `i`, INSTANCEs AssayOffice as `A`, and runs one
trace as `TSpec == TInit /\ [][TNext]_<<i,book>> /\ WF_<<i,book>>(TNext)`, so the run reaches its
last state and then stutters for ever. `Inv`, `Grows`, `Discharged` alias `A!FindingGoverns`,
`A!RecordOnlyGrows`, `A!SubstandardDischarged`, so what is held against a trace is the text in
section 1, not a copy. One cfg per run, `tc-<n>a.cfg` / `tc-<n>f.cfg`, each with
`CONSTANT Trace <- T<n>A|F`; every log is under tracelogs/.

    pair  allowed  forbidden rejected by       evidence in tracelogs/tc-<n>f.log
     1    rc=0     Req 1 FindingGoverns        rc=12, "Invariant Inv is violated by the initial state"
     2    rc=0     Req 2 RecordOnlyGrows       rc=13, action property violated, step 2->3 (at standard -> substandard)
     3    rc=0     Req 3 SubstandardDischarged rc=13, temporal property violated, "State 7: Stuttering" after state 6
     4    rc=0     Req 1 FindingGoverns        rc=12, invariant violated at state 3 (at standard and defaced)
     5    rc=0     Req 2 RecordOnlyGrows       rc=13, action property violated, step 3->4 (struck -> unmarked)
     6    rc=0     Req 2 RecordOnlyGrows       rc=13, action property violated, step 3->4 (defaced -> whole)

Allowed runs my set rejects: none; all six are rc=0. The split is two, three, one, as PROBLEM.md says.

Two controls on the harness itself. `tc-5f-narrow.cfg` holds `[][A!RecordGrows]_(A!Observe.finding)`
against pair 5's forbidden run: rc=0, "No error has been found". The single-field subscript misses
the cleared mark, exactly as requirement 2 warns. `tc-3a-nowf.cfg` holds pair 3's allowed run under
`TSpecNoWF`, the same harness without WF on TNext: rc=13, Discharged violated, the run stopping at
trace state 3 with w1 substandard and whole and then "State 4: Stuttering". So the WF conjunct is
what makes a finite allowed run checkable against a liveness property. It is not what rejects pair
3's forbidden run; that run has the WF and still fails, because its last state is the one with the
undischarged finding.

## 4. Attempts, and what TLC caught

One attempt. The first draft of the three properties and the cfg ran clean, rc=0 and 125 states,
so TLC caught nothing in it. The evidence that each property can fail therefore comes from
hand-built mutants of the shipped spec, mutants/AssayOfficeMut{A..E}.tla, each one sed edit under
the same cfg, plus the Spec control in section 2:

    A  strike guard `verdict = "atStandard"` -> `verdict /= "substandard"`  rc=12 FindingGoverns, marked clause
    B  deface guard `verdict = "substandard"` -> `verdict /= "none"`        rc=12 FindingGoverns, defaced clause
    C  test guard `verdict = "none"` -> TRUE, so re-assay is allowed        rc=13 RecordOnlyGrows, finding clause
    D  Next \/ Unstrike, which sets struck := FALSE                         rc=13 RecordOnlyGrows, marked clause
    E  Next \/ Undeface, which sets damaged := FALSE                        rc=13 RecordOnlyGrows, defaced clause

Every conjunct of every property has a run that fails it. The mutants' state counts differ from 125,
as PROBLEM.md says a changed system half must.

Revisions mid-way: none to the properties or the cfg. I added `TSpecNoWF` to the harness after the
first trace pass, to show the WF conjunct is load-bearing rather than assert it, and re-ran all
thirteen trace cfgs after that edit with the same results. Note that TLC reports an action-property
violation with rc=13, the code it uses for a temporal violation, not the rc=12 of an invariant.

## 5. Requirements I could not carry over the interface

None. All three requirements read only `finding`, `marked`, `defaced`. Rules 5 and 6 ask for nothing
to be checked, and rule 1's opening state is `Init`'s business, not a property's.

## 6. Unclear or wrong in PROBLEM.md

Nothing wrong. Two remarks. `FairSpec` quantifies WF over officers as well as wares, but `Deface(o, w)`
never mentions `o`, so `WF_vars(Deface(o1, w))` and `WF_vars(Deface(o2, w))` are the same formula and
the obligation is one per ware; the text sends the reader to look at what the conjunct is quantified
over, and the honest answer is "wares, with a decorative officer index". And the TLC log prints
"375 total distinct states" on its liveness line (125 states times 3 property branches) before the
summary's 125; a learner told to expect 125 may trip on the first number.

## 7. Mechanism family

I did not recognize this as a published problem. I recognized the general mechanism while reading
rules 2 to 4 of PROBLEM.md, before opening the module: each ware is an independent write-once record
with monotone flags, the whole a product of small state machines, with one liveness obligation
discharged by weak fairness. That shape guided the properties; the traces and mutants are what
checked them.
