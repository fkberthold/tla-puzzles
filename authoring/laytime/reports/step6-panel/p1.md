# The laytime statement, seat p1

## 1. Spec and cfg, verbatim

Laytime.tla:
```
---- MODULE Laytime ----
EXTENDS Naturals
CONSTANTS Allowance, Limit
ASSUME Allowance \in Nat /\ Limit \in Nat
VARIABLES notice, left, dem, done   \* the four facts, one variable each
vars == <<notice, left, dem, done>>
Kinds == {"working", "excepted"}    \* Rule 5: chosen inside the step, never state

TypeOK == notice \in BOOLEAN /\ left \in 0..Allowance /\ dem \in 0..Limit /\ done \in BOOLEAN
Init == notice = FALSE /\ left = Allowance /\ dem = 0 /\ done = FALSE            \* Rule 10
Tender == ~notice /\ notice' = TRUE /\ UNCHANGED <<left, dem, done>>              \* Rule 3
\* Rules 4-9. Under laytime a working period draws one, an excepted one draws
\* nothing. Once the allowance is gone the kind changes nothing: every period
\* accrues one. The cap stops logging on demurrage only; under laytime a period
\* still records a drawdown. (Only Limit = 0 tells: dem < Limit alone freezes all.)
Log(kind) ==
  /\ notice /\ ~done
  /\ left > 0 \/ dem < Limit
  /\ IF left > 0 THEN left' = (IF kind = "working" THEN left - 1 ELSE left) /\ dem' = dem
                 ELSE left' = left /\ dem' = dem + 1
  /\ UNCHANGED <<notice, done>>
Close == notice /\ ~done /\ done' = TRUE /\ UNCHANGED <<notice, left, dem>>       \* Rule 9
Next == Tender \/ (\E k \in Kinds : Log(k)) \/ Close
Spec == Init /\ [][Next]_vars                                                     \* Rule 11: no fairness

Observe == [noticeTendered |-> notice, laytimeLeft |-> left, demurrage |-> dem, finished |-> done]

OpensOnceClosesOnce ==   \* Requirement 1
  [][ /\ ~Observe.noticeTendered => /\ Observe'.laytimeLeft = Observe.laytimeLeft
                                    /\ Observe'.demurrage = Observe.demurrage
                                    /\ Observe'.finished = Observe.finished
      /\ Observe.noticeTendered => Observe'.noticeTendered
      /\ Observe.finished => Observe' = Observe ]_Observe

OnePeriodOneMove ==      \* Requirement 2
  [][ /\ Observe'.laytimeLeft = Observe.laytimeLeft \/ Observe'.laytimeLeft + 1 = Observe.laytimeLeft
      /\ Observe'.demurrage = Observe.demurrage \/ Observe'.demurrage = Observe.demurrage + 1
      /\ ~(Observe'.laytimeLeft # Observe.laytimeLeft /\ Observe'.demurrage # Observe.demurrage) ]_Observe

DemurrageWaits == Observe.demurrage > 0 => Observe.laytimeLeft = 0                \* Requirement 3
====
```
Laytime.cfg:
```
SPECIFICATION Spec
CONSTANTS
  Allowance = 2
  Limit = 2
INVARIANT TypeOK
INVARIANT DemurrageWaits
PROPERTY OpensOnceClosesOnce
PROPERTY OnePeriodOneMove
```

## 3. Traces
Method (LaytimeTrace.tla): each run is a sequence of Observe records. `Replay` walks a run with nothing
but the run constraining the variables, so a requirement can be checked on a forbidden run. `Produce`
walks it under the model's own Init and Next with INVARIANT NotAtEnd, so a violation means the model
produced the whole run. One cfg per (run, requirement) under checks/, each run on its own.
- Pair 1 forbidden (laytime falls before the notice): OpensOnceClosesOnce rc=13. The other two green.
- Pair 2 forbidden (laytime falls by two in one step): OnePeriodOneMove rc=13. The other two green.
- Pair 3 forbidden (one state, demurrage 1 with allowance 2): DemurrageWaits rc=12 on the initial state.
- Allowed 1, 2, 3 under Produce: NotAtEnd violated at i = 3, 4, 5 = Len(Trace), so the model walks all
  three to the end (checks/produce-Pair*Allowed.log). Under Replay all nine (run, requirement) checks
  are green. My set rejects no allowed run.
- Control on Produce itself: the forbidden runs stall at 1, 2 and 0 states (pair 3's opening state is
  not an Init state), so a green Produce does mean "cannot produce" and not "did not look".
Mutants, for the clauses no pair exercises. Each Mut*.tla is `Next \/ one bad step`; each requirement
was run alone against each mutant (checks/mut-*.log):
  Req 1 alone catches Withdraw, Reopen, LogAfterClose, CloseEarly (rc=13 each).
  Req 2 alone catches DoubleDem (accrues two) and Refill (excepted period gives one back).
  Req 3 alone catches EarlyDem (excepted period under laytime accrues one).
  Split (draws one and accrues one in a step) is caught by req 2 and by req 3, not by req 1.
  FreeRain (excepted period on demurrage accrues nothing, Rule 8's second half): all three green,
  11 states. That is the check behind section 5, not an assumption.

## 4. Attempts
TLC was clean on the first draft (run1.log: rc=0, 11 states). It caught nothing in it. One revision
mid-way, and TLC did not find it either: the instance sweep put Allowance=3, Limit=0 at 3 distinct
states. My Log guard was `dem < Limit`, which at Limit = 0 is false from the opening, so no period is
ever logged and the allowance can never fall. Rule 9's reason for stopping is "nothing further to
record", and under laytime that is false. The guard is now `left > 0 \/ dem < Limit`; that instance
gives 9 states and the checking instance still 11. After that, one rewrite of the file into the compact
form above so this report fits, with every check re-run; every result was identical. One shell slip
(zsh does not split `$AL` under `set --`) handed TLC a malformed cfg once; not a spec issue.

## 5. Requirements not carried
None of the three. Modelled whole but watched by nothing: Rule 8's second half, that an excepted period
on demurrage still costs one. MutFreeRain drops it and stays green, as PROBLEM.md says it must, since
the kind never reaches Observe. For the same reason an excepted period under laytime is an Observe
stutter, so a model whose working periods draw nothing would also pass; only the pairs and the state
count speak to that, and they do.

## 6. Unclear or wrong in PROBLEM.md
- Rule 9 at Limit = 0. Read literally, "once the accrued demurrage reaches it ... the agent logs no
  more periods" holds from the opening and freezes the laytime drawdown, while the rule's own reason
  ("nothing further to record") says the opposite, and "any whole-period Limit" puts 0 in scope. I took
  the reason over the letter. The statement should say which it means.
- No allowed run shows a close, an excepted period, or the cap. Nothing in the pairs checks that Close
  is producible; the 11-state count is the only thing in the problem that does.

## 7. Mechanism family
Not a published problem I recognise. On the first read of Rules 6 to 9, before writing anything, I saw
the shape: a budget drained one step at a time, then a second monotone counter behind a one-way switch,
capped, with a terminal close. A quota-then-overage, or lease-then-penalty, state machine. It changed
nothing beyond choosing four variables and no more.
