# The laytime statement — seat p2

Delivered: `Laytime.tla`, `Laytime.cfg`. Evidence only: `TraceCheck.tla`,
`Mutant.tla`, `Kindwitness.tla`, `StrictCap.tla`, `runs/` (every cfg and log).

## 1. Spec and cfg, verbatim
```tla
-------------------------------- MODULE Laytime --------------------------------
EXTENDS Naturals
CONSTANTS Allowance, Limit
ASSUME Allowance \in Nat /\ Limit \in Nat
VARIABLES notice, left, dem, closed
vars == <<notice, left, dem, closed>>

Observe == [ noticeTendered |-> notice, laytimeLeft |-> left,
             demurrage      |-> dem,    finished    |-> closed ]
TypeOK == /\ Observe.noticeTendered \in BOOLEAN /\ Observe.finished \in BOOLEAN
          /\ Observe.laytimeLeft \in 0..Allowance
          /\ Observe.demurrage \in 0..Limit

Kinds == {"working", "excepted"}                                        \* R5
Init == notice = FALSE /\ left = Allowance /\ dem = 0 /\ closed = FALSE  \* R10
Tender == ~notice /\ notice' = TRUE /\ UNCHANGED <<left, dem, closed>>   \* R3

\* R4-R8. The agent logs a period and names its kind as he writes it. While
\* allowance stands, working draws one down and excepted draws nothing; once it
\* is gone the kind buys nothing and every period accrues one. No period does
\* both. R9 stops the logging once the claim is capped.
LogPeriod(kind) ==
    /\ notice /\ ~closed /\ (left > 0 \/ dem < Limit)
    /\ IF left > 0 THEN left' = (IF kind = "working" THEN left - 1 ELSE left)
                        /\ dem' = dem
                   ELSE left' = left /\ dem' = dem + 1
    /\ UNCHANGED <<notice, closed>>
Close == notice /\ ~closed /\ closed' = TRUE /\ UNCHANGED <<notice,left,dem>> \* R9

Next == Tender \/ (\E k \in Kinds : LogPeriod(k)) \/ Close
Spec == Init /\ [][Next]_vars                            \* R11: no fairness

OpensOnceClosesOnce ==                 \* 1. The reckoning opens once, closes once.
    [][ /\ ~Observe.noticeTendered =>
              Observe' = [Observe EXCEPT !.noticeTendered = TRUE]
        /\ Observe.noticeTendered => Observe'.noticeTendered
        /\ Observe.finished => Observe' = Observe ]_Observe
OnePeriodOneMove ==                                   \* 2. One period, one move.
    [][ /\ \/ Observe'.laytimeLeft = Observe.laytimeLeft
           \/ Observe'.laytimeLeft = Observe.laytimeLeft - 1
        /\ \/ Observe'.demurrage = Observe.demurrage
           \/ Observe'.demurrage = Observe.demurrage + 1
        /\ \/ Observe'.laytimeLeft = Observe.laytimeLeft
           \/ Observe'.demurrage = Observe.demurrage ]_Observe
DemurrageWaits ==                       \* 3. Demurrage waits for the allowance.
    Observe.demurrage > 0 => Observe.laytimeLeft = 0
================================================================================
```

```
SPECIFICATION Spec
CONSTANTS
    Allowance = 2
    Limit = 2
INVARIANT
    TypeOK
    DemurrageWaits
PROPERTY
    OpensOnceClosesOnce
    OnePeriodOneMove
```

## 3. The three pairs
`TraceCheck.tla` replays each of the six runs as the only behaviour of a spec,
then asks two things: conformance (`ConformsInit`, and `ConformsStep ==
[][L!Next]_obs` — can my model produce this run) and my three requirements,
reached by INSTANCE so the text checked is the delivered text. Every allowed run
conforms and passes all three, so my set rejects none. Every forbidden run is
non-conforming and caught by its own pair's requirement and no other: pair 1 by
**req 1** (allowance drawn down before the notice), pair 2 by **req 2** (2 to 0
in one step), pair 3 by **req 3** (demurrage against a full allowance).

A rejected trace shows only non-vacuity on that run, so `Mutant.tla` checks the
delivered formulas against defective specs (`L!Next \/` one injected action).
Req 1 catches logging before the notice, withdrawing it, logging after closing;
req 2 catches drawing two off at once, accruing two at once, and doing both in
one step (req 3 catches that too); req 3 catches accruing while allowance
stands. No defect trips a requirement not its own — and req 2's body subscripted
`]_(Observe.laytimeLeft)` goes green on accrues-two: PROBLEM.md's warning, reproduced.

## 4. Attempts
One. Clean on the first run, no bug in the first draft, 11 states immediately,
nothing revised for correctness. The module was reformatted four times to fit
this report's line budget, and every check re-run against the final text. One
modelling choice changed before the first run: Rule 9's "logs no more periods",
read literally, also blocks logging at `Limit = 0` with the allowance untouched,
so I guard `(left > 0 \/ dem < Limit)`. `StrictCap.tla` is that literal reading;
over `Allowance, Limit \in 0..3` they differ only at `Limit = 0`, and both
satisfy all three requirements at all 16 instances.

## 5. What did not carry
Rule 8's second half — an excepted period on demurrage still costs one — is
modelled and unwatched, as PROBLEM.md says. `Kindwitness.tla` adds a ghost log
of each period's kind (not in `Observe`, not delivered) and TLC witnesses all
three: `<<"excepted">>` at `left = 2, dem = 0` moves no field of `Observe`;
`<<"working","working","excepted">>` and `<<"working","working","working">>`
both reach `left = 0, dem = 1`, differing only in the ghost.

## 6. Unclear or wrong
Only the Rule 9 / `Limit = 0` corner above, and it is a corner, not an error: at
the instance checked both readings give the same 11 states. Smaller: `Observe`'s
naturals are unbounded by the interface, so I bounded them in my `TypeOK`; and
"the completion is never undone" is implied by req 1's stronger third clause.
