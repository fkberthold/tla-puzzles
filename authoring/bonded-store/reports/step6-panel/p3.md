# Solution Report for Bonded Store

## 1. Properties and Configuration

### Properties (from BondedStore.tla)

**INVARIANT: Duty Paid Iff Released**
```
DutyPaidIffReleased == \A l \in Lots: dutyPaid[l] <=> place[l] = "released"
```

**PROPERTY: The Way In and Two Ways Out (action predicate + temporal wrapper)**
```
A2 == \A l \in Lots:
  \/ place[l] = place'[l]
  \/ (place[l] = "notEntered" /\ place'[l] = "inStore")
  \/ (place[l] = "inStore" /\ (place'[l] = "released" \/ place'[l] = "movedOn"))

TheWayInAndTwoWaysOut == [][A2]_Observe
```

**PROPERTY: Out Stays Out (action predicate + temporal wrapper)**
```
A3 == \A l \in Lots:
  \/ place[l] \notin {"released", "movedOn"}
  \/ (place[l] = place'[l] /\ dutyPaid[l] = dutyPaid'[l])

OutStaysOut == [][A3]_Observe
```

### Configuration (.cfg)
```
SPECIFICATION Spec
CONSTANT Lots = {l1, l2, l3}
INVARIANT DutyPaidIffReleased
PROPERTY TheWayInAndTwoWaysOut
PROPERTY OutStaysOut
CHECK_DEADLOCK FALSE
```

## 7. Mechanism Recognition
**Recognized mechanism**: This is a **state machine modeling a bonded warehouse/store system**. The mechanism is a one-way status ledger where:
- Goods (lots) have a status that can only transition forward (not backward)
- Financial state (duty paid/unpaid) is coupled to warehouse status
- Two exit paths exist (released with duty paid, or moved on with duty unpaid)

Recognition occurred when reading the problem description and the algorithm, before implementing properties. The keywords "bonded store", "duty", and "lot states" immediately signaled a customs/warehouse compliance tracking system.
