# The malting floor -- seat p2

## 1. Spec and cfg, verbatim

`Malting.tla`:
```
--------------------------- MODULE Malting ---------------------------
EXTENDS Integers
CONSTANTS Pieces, Maltsters, LowerMark, UpperMark, NoCount
ASSUME Pieces # {} /\ Maltsters # {} /\ LowerMark \in Nat /\ UpperMark \in Nat /\ LowerMark < UpperMark
VARIABLES place, turns    \* maltsters hold no state; they are bound vars
vars == <<place, turns>>
Observe == [stage |-> place, modification |-> turns]
OnFloor(p) == place[p] = "floor"
Ready(p) == turns[p] >= LowerMark /\ turns[p] < UpperMark  \* use under OnFloor
Init == place = [p \in Pieces |-> "floor"] /\ turns = [p \in Pieces |-> 0]
Turn(m, p) ==             \* rule 3: a matted piece cannot be turned
  /\ OnFloor(p)
  /\ turns[p] < UpperMark
  /\ turns' = [turns EXCEPT ![p] = turns[p] + 1]
  /\ place' = place
Kiln(m, p) ==             \* rule 4: ready in, good malt out; else a loss
  /\ OnFloor(p)
  /\ place' = [place EXCEPT ![p] = IF Ready(p) THEN "malt" ELSE "loss"]
  /\ turns' = [turns EXCEPT ![p] = NoCount]
Toss(m, p) ==             \* rule 5
  /\ OnFloor(p)
  /\ place' = [place EXCEPT ![p] = "loss"]
  /\ turns' = [turns EXCEPT ![p] = NoCount]
TakeOff(p) == \E m \in Maltsters : Kiln(m, p) \/ Toss(m, p)
Next == \E m \in Maltsters, p \in Pieces : Turn(m,p) \/ Kiln(m,p) \/ Toss(m,p)
Spec == Init /\ [][Next]_vars /\ \A p \in Pieces : WF_vars(TakeOff(p))
TypeOK ==                 \* count is Nat, not a range ending at UpperMark
  /\ place \in [Pieces -> {"floor", "malt", "loss"}]
  /\ DOMAIN turns = Pieces /\ \A p \in Pieces : turns[p] = NoCount \/ turns[p] \in Nat
Changed(p) == Observe'.stage[p] # Observe.stage[p] \/ Observe'.modification[p] # Observe.modification[p]
Req1 == Observe.stage = [p \in Pieces |-> "floor"] /\ Observe.modification = [p \in Pieces |-> 0]
Req2 == \A p \in Pieces :
          IF Observe.stage[p] = "floor"
            THEN Observe.modification[p] \in 0..UpperMark
            ELSE Observe.modification[p] = NoCount
Req3 == [][ \A p, q \in Pieces : (Changed(p) /\ Changed(q)) => p = q ]_Observe
Req4 == [][ \A p \in Pieces :
              (Observe.stage[p] = "floor" /\ Observe'.stage[p] = "floor")
                => Observe'.modification[p] \in
                     {Observe.modification[p], Observe.modification[p] + 1}
          ]_Observe
Req5 == [][ \A p \in Pieces :
              (Observe.stage[p] # "malt" /\ Observe'.stage[p] = "malt")
                => /\ Observe.stage[p] = "floor"
                   /\ Observe.modification[p] >= LowerMark
                   /\ Observe.modification[p] < UpperMark ]_Observe
Req6 == [][ \A p \in Pieces :
              Observe.stage[p] # "floor"
                => /\ Observe'.stage[p] = Observe.stage[p]
                   /\ Observe'.modification[p] = Observe.modification[p] ]_Observe
Req7 == \A p \in Pieces : <>(Observe.stage[p] # "floor")
======================================================================
```

## 2. TLC on the shipped spec
`tlc Malting -workers 1` -> **rc 0**, 2377 states generated, **216 distinct**, graph depth 10, "No error has been found" (`run-main.log`).
TLC warns that Req1 is a state-level formula under PROPERTY and so is read only at the initial states -- which is exactly what requirement 1 asks for, so the warning is the intended behaviour and not a defect.
## 3. The traces -- checked, not asserted
`TraceRun.tla` replays one run as a behaviour: `TInit /\ [][TNext]_tvars /\ WF_tvars(TNext)`. The WF conjunct walks the replay to its last state and then stutters there for ever, which is what pair 7's forbidden run says happens. 28 TLC calls (`cfgs/`, `logs/`): *props* declares my seven; *legal* declares `M!Init` and `[][M!Next]_tvars` through `INSTANCE Malting`, so "my model allows this run" is a machine check rather than a claim. Req7 is declared only for pair 7 -- every other allowed run is a finite *prefix* of a behaviour, and a liveness property cannot be judged on a prefix. **My set rejects no allowed run**: all seven pass props at rc 0 and legal at rc 0.

`Mutant.tla` then aims each property at a broken model instead of a hand-typed trace, checked against only the requirement it should break. Mut 1 opens the floor already turned -> Req1; 2 leaves the floor keeping the count -> Req2 (rc 12); 3 turns two pieces in one step -> Req3; 4 raises the count by two -> Req4; 5 kilns anything into malt -> Req5; 6 fetches a loss back to the floor -> Req6. All rc 13. Control `Mut = 0` with all seven declared: rc 0, 216 distinct states, so the mutant harness is faithful to `Malting`. `MutSpecNoFair`, the same model with fairness dropped, fails Req7 at rc 13.
## 4. Attempts, and what moved
Clean on attempt one: rc 0, 216 states, all seven passing, no revision to any step rule at any point, and TLC caught no bug in the first draft. Two choices were made before running rather than after. `Req2` uses `\in 0..UpperMark` -- set membership, never `\in Nat` and never a comparison -- so the marker answers FALSE instead of raising. And `Ready(p)` is only ever reached under an `OnFloor(p)` guard sitting to its left, so TLC's left-to-right conjunction short-circuits before the arithmetic meets the marker. The one later edit was cosmetic: the module was reflowed from 110 lines to 52 to fit this report's budget, and all 37 runs above were repeated against the reflowed file.
## 5. Requirements I could not carry
None. All seven are formulas over `Observe` alone and all seven hold. Two facts the interface genuinely cannot show, neither of them a requirement: which maltster acted (there is no field for it, so `Maltsters` is only a bound variable, and two maltsters give the same 216 states as one would), and kilning against throwing out for a piece that was not ready -- both give `stage = "loss"` with no count, so at the interface they are the same step, and the wasted fuel that separates them is by rule 4 outside the system.
## 6. On PROBLEM.md
- The typing paragraph is the only place I had to guess. "Don't type the count to the marks" and "Type the field as a range ending at `UpperMark`" read as opposite instructions. I took the second as the consequence to *avoid* -- that typing makes requirement 2 true by construction and stops it testing anything -- and left the count in `Nat`, held down only by rule 3's guard. `TypeOK` records that reading. It is the strictly harder of the two and still passes.
- Nothing forbids kilning a green piece. Rule 4 calls it a loss and wasted fuel, not impossible, so `Kiln` fires on any piece on the floor and requirement 5 constrains the outcome rather than the act. Pair 2's allowed run, floor at 0 straight to a loss, is consistent with that.
- Minor: pair 7's "nothing ever changes" note sits after the code block, not "under its last state" as the prose promises. No ambiguity in practice.
- The 216 arithmetic checks out exactly. `UpperMark + 1 = 4` counts on the floor, plus malt and loss, is 6 records per piece, and 6^3 = 216. Finding 216 and not more says my state carries nothing the interface does not ask for.
## 7. LAST -- the mechanism family
Recognised, and it is not a published problem I know. Reading rule 6, "two ways off, and no way back", against rule 2's two thresholds, before I had written a line: this is the bounded counter with an acceptance window and two absorbing terminal states. A thing matures by repeated action, is useful only inside a window, spoils past the far edge, and leaves by one of two doors that are both final. The same skeleton as a lease with a renewal window, a job against an SLA deadline, or a cache entry between warm and stale, and rule 7 is that family's liveness half: nothing may be held for ever. I noted it and kept going. It changed nothing in the model, because every rule I needed was stated in the prose.
