# SOLVE.md, seat p1: the malting floor
## 1. Module and cfg, verbatim (Malting.tla, Malting.cfg)
```
---------------------------- MODULE Malting ----------------------------
EXTENDS Naturals
CONSTANTS Pieces, Maltsters, LowerMark, UpperMark, NoCount
ASSUME LowerMark \in Nat /\ UpperMark \in Nat /\ LowerMark < UpperMark
VARIABLES stage, turns  \* turns[p] is a count on the floor, NoCount off it
vars == <<stage, turns>>
OnFloor(p)  == stage[p] = "floor"
GoneOver(p) == OnFloor(p) /\ turns[p] >= UpperMark
Ready(p)    == OnFloor(p) /\ turns[p] >= LowerMark /\ turns[p] < UpperMark
Init == stage = [p \in Pieces |-> "floor"] /\ turns = [p \in Pieces |-> 0]
Turn(m, p) == OnFloor(p) /\ ~GoneOver(p) /\ turns' = [turns EXCEPT ![p] = @ + 1] /\ UNCHANGED stage
Kiln(m, p) == OnFloor(p) /\ stage' = [stage EXCEPT ![p] = IF Ready(p) THEN "malt" ELSE "loss"]
                         /\ turns' = [turns EXCEPT ![p] = NoCount]
ThrowOut(m, p) == OnFloor(p) /\ stage' = [stage EXCEPT ![p] = "loss"]
                             /\ turns' = [turns EXCEPT ![p] = NoCount]
TakeOff(p) == \E m \in Maltsters : Kiln(m, p) \/ ThrowOut(m, p)
Next == \E m \in Maltsters, p \in Pieces : Turn(m, p) \/ Kiln(m, p) \/ ThrowOut(m, p)
Spec == Init /\ [][Next]_vars /\ \A p \in Pieces : WF_vars(TakeOff(p))
------------------------------------------------------------------------
Observe == [stage |-> stage, modification |-> turns]
Rec(o, p) == [stage |-> o.stage[p], modification |-> o.modification[p]]
Opening == \A p \in Pieces : Observe.stage[p] = "floor" /\ Observe.modification[p] = 0
CountBelongsToFloor == \A p \in Pieces :
  IF Observe.stage[p] = "floor"
    THEN Observe.modification[p] \in Nat /\ Observe.modification[p] <= UpperMark
    ELSE Observe.modification[p] = NoCount
Changed(p) == Rec(Observe', p) /= Rec(Observe, p)
OnePairOfHands == [][\A p, q \in Pieces : Changed(p) /\ Changed(q) => p = q]_Observe
TurningAddsOne == [][\A p \in Pieces :
  (Observe.stage[p] = "floor" /\ Observe'.stage[p] = "floor")
    => Observe'.modification[p] \in {Observe.modification[p], Observe.modification[p] + 1}]_Observe
ReadyIn(o, p) == o.stage[p] = "floor" /\ o.modification[p] >= LowerMark /\ o.modification[p] < UpperMark
MaltFromReady == [][\A p \in Pieces :
  (Observe.stage[p] /= "malt" /\ Observe'.stage[p] = "malt") => ReadyIn(Observe, p)]_Observe
OffIsFinal == [][\A p \in Pieces :
  Observe.stage[p] /= "floor" => Rec(Observe', p) = Rec(Observe, p)]_Observe
FloorCleared == \A p \in Pieces : (Observe.stage[p] = "floor") ~> (Observe.stage[p] /= "floor")
========================================================================

CONSTANTS Pieces = {p1, p2, p3}  Maltsters = {m1, m2}
          LowerMark = 1  UpperMark = 3  NoCount = NoCount
SPECIFICATION Spec
CHECK_DEADLOCK FALSE
PROPERTY  Opening
INVARIANT CountBelongsToFloor
PROPERTY  OnePairOfHands  TurningAddsOne  MaltFromReady  OffIsFinal  FloorCleared
```

## 4. Attempts, and mutants
TLC was clean on the first run (run-1.log: rc=0, 216 states). Run 2 is the same module with comments
stripped to fit this report; every check below was re-run on it. TLC found no bug in the draft, and
nothing changed in the semantics. A green run says little alone, so make-mutants.py builds one-edit
mutants of Malting.tla, each checked against only the property it targets (mutant-results.txt):
  M1  Init turns = 1                    -> Opening violated by the initial state (rc 13)
  M2a Kiln keeps the count              -> CountBelongsToFloor violated (rc 12)
  M2b Turn without ~GoneOver            -> CountBelongsToFloor violated (rc 12): the count passes 3
  M3  Turn raises two pieces at once    -> OnePairOfHands violated (rc 13)
  M4  Turn adds two                     -> TurningAddsOne violated (rc 13)
  M5a Kiln always makes malt            -> MaltFromReady violated (rc 13)
  M5b extra action loss -> malt         -> MaltFromReady violated (rc 13), no evaluation error
  M6  extra action loss -> floor at 0   -> OffIsFinal violated (rc 13)
  M7a no fairness at all                -> FloorCleared violated (rc 13)
  M7c WF per piece on Turn instead      -> FloorCleared violated (rc 13)
  M7b WF_vars(Next) instead             -> FloorCleared HOLDS (rc 0, 216 states); see section 6
M5b is the guard test: a NoCount piece becomes malt, MaltFromReady's antecedent is true, and the
consequent's first conjunct (stage = "floor") is false, so TLC never reaches the arithmetic.
Probe (probe/): NoCount \in Nat is FALSE, 0 = NoCount is FALSE, 0 = "none" stops TLC ("Attempted to
check equality of integer 0 with non-integer"), and NoCount <= 3 stops it too ("The first argument
of <= should be an integer"). So the IF in CountBelongsToFloor is load-bearing for the <= UpperMark
half and only belt-and-braces for the \in Nat half.
## 5. Requirements not carried
None. All seven are formulas over Observe alone; the variables appear only inside Observe and the
step rules. The maltster is bound in each action but stored nowhere, which is why the state count is
exactly the 216 the interface can show and not a multiple of it.
## 6. Unclear or wrong in PROBLEM.md
- Requirement 7 says weak fairness on the whole next-state relation "isn't what rule 7 says". As
  intent that is right, but at this instance TLC cannot tell them apart: M7b passes. Rule 3 caps
  turning at UpperMark, so a fair run has at most 9 turns and then every enabled step takes a piece
  off. A learner who checks a WF_vars(Next) draft gets green and no signal. The distinction only
  bites in a model where some non-exit action can stay enabled forever.
- Maltsters is "fixed, finite" but never said to be non-empty. With Maltsters = {} no action is
  enabled, the WF conjuncts are vacuous, and rule 7 fails while the rest hold. INFERRED, not run.
- Everything else was clear. The 216 figure, the six-records-per-piece derivation, the NoCount
  advice and the guard warning all checked out exactly as written.
## 7. Mechanism family
Not a published problem I recognise. The shape, independent per-item lifecycle automata with a
bounded monotone counter, two absorbing exits, and per-item weak fairness on the exit, I recognised
on the first read of PROBLEM.md, at rule 6 and the 216 remark, before writing any TLA+.
